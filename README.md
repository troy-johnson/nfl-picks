# NFL Picks

A small straight-up NFL pick'em app for `nflpicks.troyjohnson.dev`.

The site displays weekly win probabilities generated by a deterministic model that combines:

- rolling eight-game offensive/defensive EPA;
- rolling success rate, pass EPA, and rush EPA;
- rest and neutral-site context;
- fresh multi-book moneyline probability, with each bookmaker's margin removed;
- venue weather for outdoor/open-roof games;
- late market, favorite, and starting-QB change flags against the week's initial snapshot;
- final-run weather and recent team injury or starter news links.

## Local UI

```bash
npm install
npm run dev
```

## Generate picks

Requires Python 3.12+ and [uv](https://docs.astral.sh/uv/):

```bash
export THE_ODDS_API_KEY=...
uv run --project model python model/scheduled_runs.py
```

The command runs only when a refresh is due: Wednesday 10:00-18:00 ET, or 45-180 minutes before the next kickoff that has not started. A refresh keeps the published picks for games that already started.

Live generation requires fresh prices from at least two bookmakers for games within three hours of kickoff.
It excludes prices older than 30 minutes.
An incomplete current-season play-by-play feed or missing required odds stops publication.
Later games can use labeled nflverse fallback odds until their final window.
Cards show the odds source, bookmaker count, update time, and age at generation.

Useful options:

```bash
# Skip weather calls
uv run --project model python model/scheduled_runs.py --no-weather

# Regenerate outside a refresh window
uv run --project model python model/scheduled_runs.py --force
```

Output is written to `public/data/current.json`. The first run for a week also creates `public/data/snapshots/YYYY-WW-initial.json`; later runs compare against it for late-change warnings.

Each refresh also saves its market inputs and forecasts in `data/odds-snapshots/<season>/<day>/<timestamp>.json`.
These captures preserve earlier versions and allow another capture before each kickoff batch.

## Automation

`.github/workflows/refresh-picks.yml` creates the weekly snapshot on Wednesday.
Scheduled slots cover the 45-180 minute window before each kickoff batch, including morning, afternoon, and evening games.
The final run refreshes market, QB, weather, and news data.
Other scheduled runs exit without changing published picks.
A manual run with `force` bypasses the time window.

A changed JSON file is committed to `main`, which is intended to trigger the Vercel Git deployment.
Set `THE_ODDS_API_KEY` as a repository secret for live generation and odds capture.
`.github/workflows/capture-odds.yml` also saves independent odds captures before each kickoff batch.

The workflow also saves the frozen recency candidate, the eight-game control, and fresh odds before kickoff. Predictions enter `data/model-predictions/recency/`. Evaluation enters `data/model-evaluation/recency.json`. These records do not affect live picks. See [the forward test](docs/recency-forward.md) for the sample rules and the 250-game minimum.

## Model validation

The statistical model is trained on chronological pregame features. The prior completed season is held out to choose the market-vs-statistical blend by Brier score. After selecting that weight, the logistic model is refit on all completed games before the current week's probabilities are generated.

Run `uv run --project model python model/predict.py --backtest` to score historical games with expanding weekly training windows. The full comparison report is written to `model/artifacts/backtest.json`.

Elo, QB, combined Elo-QB, and opponent-adjusted team challengers are available in the backtest. The live model remains the V1 baseline until a challenger improves the market blend on a held-out period.

## ESPN group

`data/pool-config.json` identifies the group and Troy's entry.
The group panel reads the actual entrant count, standings, scoring rules, and dropped week from ESPN.
Live recommendations prioritize accuracy and use the higher blended win probability.

```bash
uv run --project model python model/espn_pool.py
```

The check reports matching, different, missing, and unavailable submitted picks.
ESPN can hide open picks. An unavailable pick is not a confirmed missing pick.
A complete recent entry export can verify open picks. See [the model instructions](model/README.md#submitted-pick-check).

## Data sources

- NFL schedules and play-by-play: nflverse / nflreadpy
- Stadium coordinates and timezones: greerreNFL/Stadiums
- Weather: Open-Meteo
- News links: Google News RSS
- Future moneyline snapshots: The Odds API
